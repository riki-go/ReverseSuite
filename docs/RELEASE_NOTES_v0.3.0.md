# ReverseSuite v0.3.0 - Release Notes

Released: 2026-11-09

## Headline: universal analyzer

ReverseSuite now analyses four binary families in one tool:

| Format | Inputs | Support level |
| --- | --- | --- |
| Windows PE | `.exe` `.dll` `.sys` | full: strings + xref, functions, call graph, diff, report |
| iOS Mach-O | `.ipa`, raw Mach-O | sections, `__cstring`, symbols, ARM64 functions, `cryptid`/bitcode flags |
| Android APK | `.apk` | manifest presence, every `classes*.dex`, every `lib/<abi>/*.so` |
| Dalvik DEX | `.dex` | classes, methods, fields, string table (no bytecode disassembly) |
| ELF | `.so`, Linux binaries | x86/x86-64/ARM/AArch64 sections, dynsym, ARM64 functions |

## What changed

- New `reversesuite.formats` package: `BinaryLoader` ABC plus PE, Mach-O, ELF and DEX loaders
- Magic-byte detection for PE/ELF/Mach-O (thin + fat)/DEX/ZIP, with `.apk`/`.ipa` split by member names
- `disasm` is architecture-aware: x86, x64, ARM, ARM64 engines (Dalvik skipped by design)
- Function discovery understands ARM64 prologues (`stp x29, x30, [sp, #-N]!`) and `bl` targets
- Strings come from real data sections (`__cstring`, `.rodata`) for every format, with normalized addresses
- `.apk`/`.ipa` are unpacked in memory; members are analysed recursively with per-member attribution
- CLI `analyze` and the HTTP API route non-PE inputs through the new pipeline
- UI accepts `.apk`/`.ipa`/`.so`/`.dex` (file picker and drag & drop)

## Compatibility

- PE behaviour is unchanged: the original loader path is still used, 155 legacy tests still pass
- Schema version stays `1.0.0`; new findings use newly registered rule ids

## Verification

- Unit tests: 177/177 passing (155 legacy + 22 new multi-format tests)
- Fixtures `fixtures/multi/*` are generated by `fixtures/gen_multi.py` and cross-checked with LIEF
  (ELF `ARCH.AARCH64`, Mach-O 1 slice, DEX 6 strings)

## Known limitations

- Dalvik bytecode is inventoried, not disassembled
- iOS binaries with FairPlay encryption (`cryptid != 0`) yield ciphertext; the diagnostic says so
- `.ipa` frameworks are listed and parsed only when their binary is easy to locate
- Android `resources.arsc` / binary `AndroidManifest.xml` are not decoded yet
- Inter-procedural analysis (M6.2) and vtable/RTTI recovery (M6.3) remain deferred
